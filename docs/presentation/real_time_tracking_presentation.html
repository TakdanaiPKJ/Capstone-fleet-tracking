ข้อจำกัดเวลา

ตามมาตรฐาน มอก. คอนกรีตผสมเสร็จต้องถูกเทให้หมดภายใน 1 ชม. 30 นาที (90 นาที) เพื่อรักษาคุณภาพ

สเกลธุรกิจขนาดใหญ่

ฝูงรถโม่มากกว่า 90 คัน, แพลนต์ 10-20 แห่ง และมีเที่ยวจัดส่งกว่า 300 เที่ยว/วัน

ปัญหาของระบบเดิม

ระบบ GPS เดิมไม่มีแนวคิดของ "เที่ยวขนส่ง"
ไม่มีเส้นทางปลายทาง
ไม่มีระบบ ETA (ต้องกะเวลาเอง)

ความท้าทายทางวิศวกรรม (Problem Statement)

1. Noisy & Sparse Data

GPS มีสัญญาณรบกวน และส่งข้อมูลพิกัดเพียงทุกๆ 30 วินาที อาจทำให้พลาดจังหวะการเข้า-ออกขอบเขต

2. Uncertainty

เวลาเดินทางไม่แน่นอน ผันแปรตามสภาพการจราจรจริงและเวลาการทำงานที่หน้าไซต์

3. Asynchronous Integration

ตารางงานจากระบบจอง (ภายนอก) อาจมาล่าช้ากว่าการออกเดินทางจริงของรถ

4. Scale & Speed

ปริมาณข้อมูลสูงถึง 94.6 ล้านแถวต่อปี แต่ระบบต้องแสดงผลการเคลื่อนไหวภายใน 5 วินาที

5. Cold Start / Testing

ไม่มีข้อมูลจริงในช่วงการพัฒนา ต้องสร้าง Simulator ขั้นสูงเพื่อจำลองและทดสอบระบบ

Real-time Map

แสดงตำแหน่ง สถานะ และเส้นทางของรถทุกคันบนแผนที่แบบเรียลไทม์ ในหน้าจอเดียว

O2

ตรวจจับเหตุการณ์และสถานะของเที่ยวขนส่งโดยอัตโนมัติ โดยอาศัยเทคโนโลยี Geofence

O3

ETA Engine

ประมาณเวลาถึงไซต์งาน (Arrival-at-site) และเวลากลับถึงแพลนต์ (Return-to-plant)

เทียบเวลาตามแผนกับเวลาจริง และแจ้งเตือนทันทีเมื่อพบเที่ยวขนส่งที่มีแนวโน้มล่าช้า

O5

High Usability

ออกแบบระบบให้ใช้งานง่าย (User Friendly) เพื่อให้เจ้าหน้าที่สามารถย้ายจากระบบเดิมมาใช้งานได้ทันที

O6

KPIs & Integration

คำนวณ KPI เก็บประวัติย้อนหลัง และมี API สำหรับส่งข้อมูล ETA กลับไปยังระบบจัดตารางงาน

การเปรียบเทียบระบบ (Gap Analysis)

ความสามารถหลัก ระบบ GPS เดิม (ปัจจุบัน) ระบบ RMC เฉพาะทาง ระบบที่นำเสนอ
แนวคิดเที่ยวขนส่ง (Trip Notion) ไม่มี (มีแค่ POI) มี (ต้องติดเซนเซอร์) มี (ใช้อัลกอริทึม)
ประมาณเวลาถึง (ETA) แบบเรียลไทม์ ไม่มี ไม่ระบุชัดเจน มี (OSRM + ประวัติ)
การใช้อุปกรณ์ GPS เดิมที่มีอยู่ ใช้ของเดิม ต้องซื้อฮาร์ดแวร์ใหม่ ซอฟต์แวร์ครอบทับเดิม

ช่องว่าง (Gap): การสร้าง Software Intelligence ครอบทับอุปกรณ์ที่มีอยู่ เพื่อแปลงข้อมูลดิบให้เป็นข้อมูลเที่ยวขนส่งและ ETA โดยไม่ต้องลงทุนด้านฮาร์ดแวร์เพิ่มเติม

Geofence Logic & Hysteresis

  • แพลนต์ (Plant): ระยะขาเข้า 50m / ขาออก 80m
  • ไซต์งาน (Site): ระยะขาเข้า 100m / ขาออก 150m
  • การกำหนดระยะต่างกัน (Hysteresis) ช่วยป้องกันระบบสร้างเหตุการณ์หลอกกรณีพิกัด GPS แกว่งอยู่บริเวณขอบ

Handling Sparse Data

เนื่องจากอุปกรณ์ส่งพิกัดมาทุกๆ 30 วินาที รถอาจจะวิ่งทะลุขอบเขตไปแล้ว

ระบบใช้ Linear Interpolation
ประมาณค่าเวลาข้ามขอบที่แท้จริงระหว่าง 2 จุดล่าสุด

อัลกอริทึม ETA Engine

การคำนวณเวลาถึงไซต์งานและเวลากลับถึงแพลนต์ โดยผสมผสานระบบ Routing และข้อมูลประวัติ

ETA_site = t_now + ( f × T_base )
ETA_plant = ETA_site + D_site + ( f × T_return )

ตัวแปรที่ใช้ (Variables)

  • T_base / T_return

    เวลาเดินทางอ้างอิงจาก OSRM (ไม่รวมผลกระทบการจราจร)

  • f (Multiplier)

    ค่าปรับสถิติจราจรย้อนหลัง แยกตามเส้นทาง(แพลนต์-ไซต์) และรายชั่วโมง ระบบจะอัปเดตค่า f ใหม่ทุกคืน

  • D_site

    เวลาปฏิบัติงานประเมินที่หน้าไซต์ (ขึ้นอยู่กับประเภทงานเทและปริมาณคอนกรีต)
